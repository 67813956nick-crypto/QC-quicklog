# QC-quicklog 网页版部署指南（V7.10）

> 目标：把本地 HTML 工具变成「给链接就能用」的网页版，解决「每次发文件 + 教别人用浏览器打开 + 各浏览器表现不一」的痛点。
> 部署方式：**自有 Linux 服务器 + nginx 静态托管 + HTTP Basic 口令**（公网访问推荐再加 HTTPS）。

---

## 一、为什么这样部署就行

- 工具是**纯前端单文件**（168K，零外部 CDN、零后端、零数据库）。
- 导入（FileReader 读本地文件）、导出（Blob 生成本地文件）**全部在用户浏览器内完成，文件不会上传到服务器**。
- 因此服务器只负责「把 `index.html` 这个静态文件发给浏览器」，nginx 是最轻量稳妥的选择。
- 经 HTTP 提供后，Chrome / Edge / Firefox / Safari 行为完全一致——这正是消除「各浏览器不一样」的根本原因（之前差异来自 `file://` 本地打开）。

---

## 二、部署步骤（约 5 分钟）

### 1. 取部署文件
仓库 `deploy/` 目录下已备好：
- `index.html` —— 即 V7.10 工具本体（已加浏览器一致性页脚提示）
- `nginx-qc-quicklog.conf` —— nginx 站点配置模板

```bash
# 在服务器上
sudo mkdir -p /var/www/qc-quicklog
# 把本仓库 deploy/index.html 传到服务器该目录
# （例：本地 scp）
# scp deploy/index.html user@你的服务器IP:/var/www/qc-quicklog/index.html
```

### 2. 放 nginx 配置
```bash
# 把 deploy/nginx-qc-quicklog.conf 传到服务器
sudo cp nginx-qc-quicklog.conf /etc/nginx/conf.d/qc-quicklog.conf
# 编辑：把 server_name 改成你的域名或公网IP
sudo vi /etc/nginx/conf.d/qc-quicklog.conf
```

### 3. 设置访问口令（公网必做）
```bash
# 安装工具（Debian/Ubuntu）
sudo apt install -y apache2-utils
# 生成口令文件（-b 明文传入，-c 首次创建）
sudo htpasswd -bc /etc/nginx/.htpasswd_qc 你的用户名 你的密码
# 没有 htpasswd 时的替代：
#   sudo sh -c "echo '你的用户名:'$(openssl passwd -apr1 '你的密码') > /etc/nginx/.htpasswd_qc"
```

### 4. 校验并重载
```bash
sudo nginx -t          # 语法检查，看到 successful 再继续
sudo systemctl reload nginx
```

### 5. 开放端口 / 防火墙
- 云厂商安全组 + 服务器防火墙都要放行 **80**（HTTP）端口。
- 内网使用：确保访问者能通到服务器的 80 端口即可。

### 6. 访问验证
浏览器打开 `http://你的域名或IP` → 输入口令 → 看到「材料质量证明文件快速录入 V7.10」标题即成功。
导入一份质保书 JSON/MD 自检：条数、字段、分类与本地一致。

## 三、升级到 HTTPS（公网推荐，免费）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
# 按提示选重定向，certbot 会自动把 80 改 301 跳 443 并配好证书
# 证书 90 天自动续期（certbot 已装定时器）
```
> 仅内网/临时使用可跳过 HTTPS，但**口令（Basic Auth）仍建议保留**，避免无关人误入。

## 四、后续发新版流程（铁律延伸）

代码在 `材料录入桥接工具_v7.10.html`，部署副本在 `deploy/index.html`。发版时：

```bash
# 1. 本地改完并跑回归（见 docs/开发规范.md 铁律一）
node test_v74_json.js
# 2. 同步到 deploy 副本
cp 材料录入桥接工具_v7.10.html deploy/index.html
# 3. 上传到服务器覆盖 /var/www/qc-quicklog/index.html
# 4. 无需重启 nginx（HTML 设了 no-cache，刷新即生效）
```
> 因 nginx 对 `.html` 设了 `no-cache`，更新文件后用户**强刷一下（Ctrl+F5）**即可拿到最新版。

## 四点五、V7.10 扫描件直传（MinerU API 反代）

V7.10 新增「PDF/图片扫描件直传」：浏览器上传 → MinerU 解析 → 自动入表，全程百分比进度。
因 MinerU API 与结果 CDN 均**拒绝浏览器跨域（CORS 实测 403）**，必须由服务器反代；
Token 只存服务器 nginx 配置，**不进前端代码、不进 git**。

### 部署步骤（宝塔，细化版）

**第 0 步：拿可用 API Token**
- mineru.net → 右上角头像 → **API 管理**（https://mineru.net/apiManage）→ 创建/复制 **Token**
- ⚠️ 控制台首页的 Access Key/Secret Key **不是** API Token（实测 401 A0202）
- **Token 是否可用以真实 API 响应为准**，不能只看控制台「有效」，也不能凭单次 A0211 就断定 Token 过期、只读或未审批。2026-11-20 两枚 Token 曾返回 A0211，2026-11-21 使用相同 Token、相同端点和参数复测均返回 `code:0`，说明该错误可能受账号或网关状态变化影响
- 遇 A0211：用本节末尾的最小 curl 请求复测并保存 `trace_id`；确认 Token 无抄错、无首尾空格，稍后做同参数对照复测。若控制台页面明确要求 API 申请或手机绑定，再按页面提示完成，不把这些流程当作所有账号的固定前置

**第 1 步：conf 放哪里（两种方式，推荐方式 A）**

**方式 A（推荐）：粘进站点配置，不落独立文件**
1. 宝塔面板 → **网站** → 找到 `nickpang.cn` → 点 **设置**
2. 左侧选 **配置文件**（就是该站点的 nginx server 块，对应服务器文件 `/www/server/panel/vhost/nginx/nickpang.cn.conf`）
3. 打开本地 `deploy/mineru-proxy.conf`，把**三段 `location {...}`**（从 `# ---------- 1.` 到文件末尾）复制
4. 粘贴到配置文件中 **`server {` 之后、第一个已有 `location` 之前**（不要贴到 server 块外面，不要动已有的 `location /` 和 SSL 段）
5. 把粘贴内容里的 `<你的MinerU_Token>` 替换为第 0 步的真实 Token（**只有一处**，在 `/mineru-api/` 段的 `proxy_set_header Authorization` 行）
6. 点 **保存** → 宝塔自动 `nginx -t` 校验并重载；若报语法错误会提示行号，检查大括号配对

**方式 B（独立文件 + include，适合喜欢文件管理的）**
1. 宝塔 → **文件** → 进入 `/www/server/panel/vhost/nginx/` → 新建文件 `mineru-proxy.conf`
2. 把本地 `deploy/mineru-proxy.conf` 的三段 location 内容贴进去，替换 Token，保存
3. 回到站点 **配置文件**，在 `server { }` 内加一行：
   `include /www/server/panel/vhost/nginx/mineru-proxy.conf;`
4. 保存（自动校验重载）
- ⚠️ 方式 B 的文件权限建议 600（含密钥）：文件管理器里右键 → 权限 → 600，属主 www

**第 2 步：上传新版前端**
- 宝塔 → 文件 → `/www/wwwroot/nickpang.cn/QC-list/` → 上传本地 `deploy/index.html` **覆盖**同名文件
- 建议覆盖前先把线上旧 index.html 下载一份留底（回滚用）

**第 3 步：验证（按顺序）**
1. 浏览器开 `http://nickpang.cn/QC-list/` → **Ctrl+F5 强刷** → 标题应为 V7.10，导入区右侧出现「PDF/图片扫描件」卡片
2. 先验反代通不通：浏览器地址栏开 `http://nickpang.cn/mineru-api/v4/extract-results/batch/test` → 应返回 MinerU 的 JSON（如 `{"code":...,"msg":...}`），**而不是 404/502**；返回鉴权类错误码说明 Token 没填对
3. 拖一张真实质保书扫描件进右侧卡片 → 应看到：上传% → 排队 → 逐页解析% → 下载 → 入表条数
4. 若上传阶段报错：检查 `/mineru-oss/` 段是否粘贴完整（OSS 域名长，容易截断）
5. 若下载阶段报错：检查 `/mineru-cdn/` 段

**回滚**：把站点配置里粘贴的三段 location 删掉保存 + 传回旧 index.html 即可，互不影响其它功能。

### 三个高频坑（线上部署踩坑记录，均已固化）

**坑 A：`Unexpected token '<'`（相对路径 + 子目录）**
- 工具部署在**子目录**（如 `/QC-list/`）时，前端 `MINERU_API_BASE='mineru-api'` 等**相对路径**会被解析成 `/QC-list/mineru-api/...`，不命中根反代 → 404 HTML。
- 判定：手动访问 `http://你的域名/mineru-api/v4/...` 能返回 JSON，但工具页地址栏在子目录下（不是根目录）。
- 修复：前端三处改**绝对路径**（`/mineru-api`、`/mineru-oss/`、`/mineru-cdn/`），已固化进 V7.10 收尾版。

**坑 B：`Unexpected token 'I'` / `Invalid CORS request`（浏览器 Origin 头）**
- 浏览器发请求自动带 `Origin` 头，MinerU 后端（Spring）CORS 校验拒绝（403）；curl 不带 Origin 所以能通。
- 判定：`curl -H "Origin: http://你的域名" -X POST http://你的域名/mineru-api/v4/file-urls/batch -H "Content-Type: application/json" -d "{}"` 返回 `Invalid CORS request`，去掉 `-H "Origin..."` 后返回 JSON。
- 修复：nginx 三段 location 各加 `proxy_set_header Origin "";` 与 `proxy_set_header Referer "";`（`Origin` 是浏览器「禁止修改头」，JS 删不掉，只能在 nginx 层清空）。

**坑 C：`.png/.jpg` 上传 404/405（宝塔图片正则拦截）**
- 宝塔默认 `location ~*` 图片正则把 `.png` 等后缀拦成 404/405。
- 修复：三段 location 加 `^~` 前缀，跳过正则匹配。

### 数据流与额度

- 上传：`/mineru-oss/` → 阿里 OSS 预签名 PUT（≤200MB/文件，≤200页，单批≤50个）
- 解析：`is_ocr=true` + `pipeline` 模型（对齐现有 fixtures 的输出格式）
- 结果：`/mineru-cdn/` 下载 zip → 浏览器内解压取 `*_middle.json`（= pdf_info 格式）→ 喂 V7.9 规则解析器
- 额度：官方文档口径为每账号每天 **1000 页高优先级**（超出仍可解析、排队变慢）；新版控制台按「份文件」显示每日总额度（基础+额外申请，如 5000 份），每日 0 点重置；错误码 -60018=当日任务数上限；官方无剩余量查询接口，页面「今日已用」为本机 localStorage 统计
- Token：控制台创建的 API Token 页面说明有效期 **90 天**（到期需重建）。A0211 只代表当次网关鉴权未通过，**不能直接等同于 Token 永久失效或只读**；应按第 0 步做同参数复测并保留 `trace_id`
- 部署前必验：`curl -X POST https://mineru.net/api/v4/file-urls/batch -H "Authorization: Bearer <Token>" -H "Content-Type: application/json" -d "{\"files\":[{\"name\":\"p.pdf\"}]}"` 返回 `code:0` 才把 Token 填进 conf
- ⚠️ 使用直传功能时扫描件会上传 MinerU 官方服务（页脚已声明）；JSON 导入/导出仍全本机

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开是 nginx 默认页 | `server_name` 没匹配到；或文件没放到 `/var/www/qc-quicklog/index.html`；`nginx -t` 看报错 |
| 提示 403 | `.htpasswd_qc` 路径错或权限不足（nginx 用户需可读）；或 root 目录权限问题 |
| 中文乱码 | 确认 nginx 配置里有 `charset utf-8;` 且 HTML 含 `<meta charset="UTF-8">` |
| 改了 HTML 不生效 | 浏览器缓存，Ctrl+F5 强刷；或没覆盖到服务器上的 index.html |
| 扫描件直传报 `Unexpected token '<'` | 工具在子目录（如 `/QC-list/`）部署但前端用相对路径 → 改绝对路径 `/mineru-api` 等 |
| 扫描件直传报 `Invalid CORS request` / `Unexpected token 'I'` | 浏览器带 Origin 头被 MinerU 拒绝 → nginx 三段 location 加 `proxy_set_header Origin "";` |
| `.png/.jpg` 直传 404/405 | 宝塔图片正则拦截 → 三段 location 加 `^~` 前缀 |
| 想换端口（如 8080） | `listen 8080;` 并放行该端口；URL 带 `:8080` |
| 多人不同权限 | Basic Auth 只做「有没有口令」，不做分用户；如需分人，给每人单独账号（`htpasswd -b` 追加）|

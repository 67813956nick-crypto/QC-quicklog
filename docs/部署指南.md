# QC-quicklog 网页版部署指南（V7.7）

> 目标：把本地 HTML 工具变成「给链接就能用」的网页版，解决「每次发文件 + 教别人用浏览器打开 + 各浏览器表现不一」的痛点。
> 部署方式：**自有 Linux 服务器 + nginx 静态托管 + HTTP Basic 口令**（公网访问推荐再加 HTTPS）。

---

## 一、为什么这样部署就行

- 工具是**纯前端单文件**（168K，零外部 CDN、零后端、零数据库）。
- 导入（FileReader 读本地文件）、导出（Blob 生成本地文件）**全部在用户浏览器内完成，文件不会上传到服务器**。
- 因此服务器只负责「把 `index.html` 这个静态文件发给浏览器」，nginx 是最轻量稳妥的选择。
- 经 HTTP 提供后，Chrome / Edge / Firefox / Safari 行为完全一致——这正是消除「各浏览器不一样」的根本原因（之前差异来自 `file://` 本地打开）。

---

## 二、部署步骤（约 5 分钟）

### 1. 取部署文件
仓库 `deploy/` 目录下已备好：
- `index.html` —— 即 V7.7 工具本体（已加浏览器一致性页脚提示）
- `nginx-qc-quicklog.conf` —— nginx 站点配置模板

```bash
# 在服务器上
sudo mkdir -p /var/www/qc-quicklog
# 把本仓库 deploy/index.html 传到服务器该目录
# （例：本地 scp）
# scp deploy/index.html user@你的服务器IP:/var/www/qc-quicklog/index.html
```

### 2. 放 nginx 配置
```bash
# 把 deploy/nginx-qc-quicklog.conf 传到服务器
sudo cp nginx-qc-quicklog.conf /etc/nginx/conf.d/qc-quicklog.conf
# 编辑：把 server_name 改成你的域名或公网IP
sudo vi /etc/nginx/conf.d/qc-quicklog.conf
```

### 3. 设置访问口令（公网必做）
```bash
# 安装工具（Debian/Ubuntu）
sudo apt install -y apache2-utils
# 生成口令文件（-b 明文传入，-c 首次创建）
sudo htpasswd -bc /etc/nginx/.htpasswd_qc 你的用户名 你的密码
# 没有 htpasswd 时的替代：
#   sudo sh -c "echo '你的用户名:'$(openssl passwd -apr1 '你的密码') > /etc/nginx/.htpasswd_qc"
```

### 4. 校验并重载
```bash
sudo nginx -t          # 语法检查，看到 successful 再继续
sudo systemctl reload nginx
```

### 5. 开放端口 / 防火墙
- 云厂商安全组 + 服务器防火墙都要放行 **80**（HTTP）端口。
- 内网使用：确保访问者能通到服务器的 80 端口即可。

### 6. 访问验证
浏览器打开 `http://你的域名或IP` → 输入口令 → 看到「材料质量证明文件快速录入 V7.7」标题即成功。
导入一份质保书 JSON/MD 自检：条数、字段、分类与本地一致。

## 三、升级到 HTTPS（公网推荐，免费）

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
# 按提示选重定向，certbot 会自动把 80 改 301 跳 443 并配好证书
# 证书 90 天自动续期（certbot 已装定时器）
```
> 仅内网/临时使用可跳过 HTTPS，但**口令（Basic Auth）仍建议保留**，避免无关人误入。

## 四、后续发新版流程（铁律延伸）

代码在 `材料录入桥接工具_v7.7.html`，部署副本在 `deploy/index.html`。发版时：

```bash
# 1. 本地改完并跑回归（见 docs/开发规范.md 铁律一）
node test_v74_json.js
# 2. 同步到 deploy 副本
cp 材料录入桥接工具_v7.7.html deploy/index.html
# 3. 上传到服务器覆盖 /var/www/qc-quicklog/index.html
# 4. 无需重启 nginx（HTML 设了 no-cache，刷新即生效）
```
> 因 nginx 对 `.html` 设了 `no-cache`，更新文件后用户**强刷一下（Ctrl+F5）**即可拿到最新版。

## 六、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开是 nginx 默认页 | `server_name` 没匹配到；或文件没放到 `/var/www/qc-quicklog/index.html`；`nginx -t` 看报错 |
| 提示 403 | `.htpasswd_qc` 路径错或权限不足（nginx 用户需可读）；或 root 目录权限问题 |
| 中文乱码 | 确认 nginx 配置里有 `charset utf-8;` 且 HTML 含 `<meta charset="UTF-8">` |
| 改了 HTML 不生效 | 浏览器缓存，Ctrl+F5 强刷；或没覆盖到服务器上的 index.html |
| 想换端口（如 8080） | `listen 8080;` 并放行该端口；URL 带 `:8080` |
| 多人不同权限 | Basic Auth 只做「有没有口令」，不做分用户；如需分人，给每人单独账号（`htpasswd -b` 追加）|

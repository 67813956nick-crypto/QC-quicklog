# QC-quicklog 材料质量证明文件快速录入

石化项目材料质量证明文件（质保书/合格证）快速录入工具。上传 MinerU 解析的 JSON 文件，自动解析阀门、对焊法兰、管材、紧固件、垫片、管件、支吊架等物资信息，补填自编号后一键导出底表与 SH/T 3503—J132 一览表。

## 物资分类（7类）

| 分类 | 识别关键词 | 默认单位 |
|---|---|---|
| 阀门 | 闸阀/球阀/蝶阀/截止阀/止回阀 | 台 |
| 对焊法兰 | 法兰/FLANGE | 片 |
| 管材 | 钢管/焊管/流体输送（**不含"无缝"**，见下） | 吨/KG/m |
| 紧固件 | 螺栓/螺柱/螺母 | 套 |
| 垫片 | 缠绕垫/垫片 | 件 |
| 管件 | 弯头/三通/异径管/管箍/管帽/大小头/管座/封头/短节/管堵 | 件 |
| **支吊架**（V7.4新增） | 吊架/支吊架/碟簧吊架/弹簧支架 | 套 |

> 支吊架独立分类，**不属于管件**（如可变碟簧吊架）。

> **⚠️ 分类口径（V7.7 修正，业务定义）**：**管材 = 钢管类别**；**管件 = 三通、弯头、大小头等配件**。
> "无缝"是**工艺描述，不是品类**，已从管材识别词中移除——否则"无缝弯头90°""无缝三通"会被误判为管材。
> 识别顺序：**管件优先于管材**。完整定义见 [`docs/开发规范.md`](docs/开发规范.md)。

## 使用

1. 用浏览器打开 `材料录入桥接工具_v7.7.html`
2. 上传 MinerU 解析出的 JSON 文件（**可一次多选多个**），见 `tests/fixtures/` 样例格式
3. 解析结果自动填入底表，所有字段可直接修改，行首 🗑️ 可删除整行
4. 填好工具栏「工程名称」，导出：底表 CSV / 一览表 Word / 检测委托单 Word

> 单 HTML 文件，无需安装依赖，双击即用。

**导出说明（V7.6）**

| 按钮 | 输出 | 说明 |
|---|---|---|
| 导出底表CSV | `.csv` | 14 列底表，证件自编号空填"/" |
| 导出一览表Word | `.doc` | 对齐 SH/T 3503—J132 模板版面，超 18 条自动分页带（续） |
| 导出检测委托单 | `.doc` | 对齐 SH/T 3543—G128 模板，每页 9 条；检件名称=产品名称、质量证明文件编号=证书出厂编号、炉/批号=炉号(无则批号)、工单/网络号=工单号；空白栏位手填后打印 |

> 检测委托单的**工单/网络号**来自解析时从 JSON 表格抓取的「工单号」字段（底表不显示），无则留空。

## 开发规范（三条铁律）

> **改代码前必读。** 完整版见 [`docs/开发规范.md`](docs/开发规范.md)。
> 制定背景：V7.6「看似稳定」却在遇到序号29 新数据变体时一次性暴露两个潜伏 bug（漏 1 条 + 分类误判）。

### 铁律一：新 JSON 必须过回归测试，不许直接导入

任何新增序号 JSON 到货，**先跑 `node test_v74_json.js`，全绿才允许交付**。验收三条：
1. **条数正确** —— 解析条数 == JSON 页数，不允许少一条
2. **关键字段无空** —— 规格型号、炉号/批号、证书出厂编号、材质、数量
3. **分类正确** —— 按业务定义核对

**新增序号 = 新增测试断言**：JSON 放进 `tests/fixtures/`，在测试脚本补预期值。

### 铁律二：解析器检测条件禁止使用「前 N 行」假设

```javascript
// ❌ 错误：假设特征词一定在前 5 行
var rowStr = table.slice(0, 5).map(r => r.join('|')).join('|');
// ✅ 正确：全表扫描，不依赖行号
var rowStr = table.map(r => r.join('|')).join('|');
```

取字段用 `kvLookup(table, keyPattern)` **整表按 key 定位**，不按固定行号硬取值。
> 原因：同一厂家不同批次的表格可能多出"收货单位"等首行，把特征词挤出前 N 行 → 检测失败 → 字段全乱。

### 铁律三：分类规则按业务定义固化，改动需三处同步

新增/修改物资类型时，**三处必须同步**，缺一不可：

| # | 位置 | 说明 |
|---|---|---|
| 1 | `rules/8.28-V7.4规则更新.xlsx` | 规则表，业务口径唯一来源 |
| 2 | `classifyProduct()` | 代码实现，必须与规则表一致 |
| 3 | `test_v74_json.js` | 测试断言，钉死预期分类 |

**不许为了"匹配上"而放宽正则**——用工艺描述词（如"无缝"）当品类依据，从根上就是错的。

### 数据安全红线

代码中**禁止出现任何业主单位名称**；制造厂家识别用**纯标签驱动**（客户名称/Customer/项目名称/Project Name/采购单位）；工具**不读取、不保存、不输出**业主单位/项目名称字段。提交前跑敏感词扫描（命令见规范文档）。

## 新增序号工作流（V7.7约定）

> **以后直接丢 JSON 给 AI 即可**，AI 会同步更新以下 5 处，形成闭环：

1. **解析器**（当前版本 HTML）：新增/扩展解析函数 + 厂家映射（**检测条件必须全表扫描**，铁律二）
2. **规则文件**（`rules/8.28-V7.4规则更新.xlsx`）：追加序号行，写明厂家/型号/分类（铁律三 ①）
3. **分类**（`classifyProduct`）：按业务定义判断，**不放宽正则**（铁律三 ②）
4. **测试用例**（`test_v74_json.js` + `tests/fixtures/`）：新增 expectedData + 文件映射（铁律三 ③）
5. **文档**（`CHANGELOG.md` / `README.md`）：记录新增序号与分类变化

**交付前必须**：跑 `node test_v74_json.js` 全绿（铁律一）+ 敏感词扫描，两条缺一不可交付。

**分类注意**：新增物资类型时先判断是否属于现有 7 类（阀门/对焊法兰/管材/紧固件/垫片/管件/支吊架），若为全新类型（如支吊架），需同步扩展 `classifyProduct` 并更新规则表头分类数。

**参考**：完整流程、环境注意事项（分支名不用斜杠、`git reset --hard` 会删未跟踪文件）见 [`docs/开发规范.md`](docs/开发规范.md)。
